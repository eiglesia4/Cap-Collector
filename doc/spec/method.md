# Working method — architect, dev agents, integrator (CapCollector)

**Status:** Agreed (2026-10-31) · Adapted from `Metodo_Agentico_Seshet_v1.1` (Naevatec). Same mechanics, fewer territories.

## Roles and write boundaries

| Role | Lives in | Writes | Never writes |
|---|---|---|---|
| **Architect** | Cowork (this project) | `docs/**` in the OneDrive folder and its frozen copy `doc/spec/` in the repo; **contracts**: `shared/src/**` (zod schemas + TS types: Cap, Location, Exchange v1), `doc/spec/openapi.yaml`, DynamoDB key schema; Jira; `CLAUDE.md`, `OWNERSHIP.md`, `.claude/commands/` | app or API code, tests, CDK |
| **dev-app** | Claude Code, own worktree | `app/**` (Vite + Capacitor UI, client dHash, PDF, exchange bundles) and its tests | `shared/`, `api/`, `infra/`, `package.json` |
| **dev-api** | Claude Code, own worktree | `api/**` (Lambda handlers, DynamoDB access, Bedrock call, presigned URLs, auth) and its tests | `shared/`, `app/`, `infra/`, `package.json` |
| **Integrator** | Claude Code `/integrate` | `main` (rebase, checks, squash merge, `CHANGELOG.md`, tags), `infra/**` (CDK), `deploy/**`, `.github/**`, root `package.json`/workspaces | business logic |
| **Edu** | Jira + PR review + device | decisions, GO on PRs, `cdk deploy`, App Store / TestFlight | — |

Rule: **code never changes a contract.** A story that needs a new field or endpoint → conservative choice, `// SPEC-GAP CAP-<n>: …` in code, listed under *Spec deviations* in the Jira closing comment; the architect versions the contract.

## Jira project `CAP`
- Workflow (same as SESHET): **Backlog · Ready · In Progress · In Review · Blocked · Done**. Ready = can start now (no *is blocked by* link to anything not Done).
- Epics = components (EP-01 … EP-10). Stories = commit-sized, testable, one territory each.
- Labels: `area-app` · `area-api` · `area-infra` · `design` (architect resolves) · `needs-human` (Edu's dashboard) · `deliverable-V0…V4` · `cap-<epic slug>`.
- Versions (Kanban milestones): **V0 skeleton** · **V1 manual collection** · **V2 scan & AI** · **V3 album link** · **V4 phase 2**.
- Story package before Ready: spec referenced (file + section), allowed paths, test IDs `T-<comp>-nnn` (`comp` ∈ `app · api · shared · infra · vision · print · exchange`), acceptance criteria, `area-*` label, deliverable label.
- Closing comment (English, parsed by the dashboard): first line `[cap-status] agent=<name> ticket=CAP-<n> state=<in_progress|in_review|blocked|done>`, then **Done · Tests · Spec deviations · Pending · PR · Needs human**.

## Git
- Repo `capcollector` (GitHub, private). Branch `CAP-<n>-<slug>` from `main`; one worktree per agent (`../capcollector-wt/CAP-<n>`); one story = one PR; squash merge by the integrator only; author = Edu (no agent co-author lines); `pre-push` hook blocks direct push to `main`; `gitleaks` pre-commit.
- Commits `CAP-<n>: <what>` in English. PR body: Done · Tests · Spec covered · Deviations.
- Tags per milestone: `v0.1.0-v0`, `v0.2.0-v1`, `v0.5.0-v2`, `v0.8.0-v3`, `v1.0.0-v4`.

## Tests
- IDs `[T-<comp>-nnn]` at the start of every test title, never reused. `TEST.md` generated by `npm run catalog`, regenerated in the same commit.
- No cloud in tests: DynamoDB Local + S3 mock (or in-memory repository behind an interface); Bedrock behind an adapter with fixtures; `vitest` everywhere. Capacitor-only code behind a thin `platform/` adapter so the web build tests it.
- Coverage ≥ 80 % per package.

## Commands (`.claude/commands/`)
`/next` · `/revise CAP-<n>` · `/handoff` · `/integrate [--auto] [--release <tag>]` — copies of the Seshet commands with `SESHET→CAP`, `SESHET_AGENT→CAP_AGENT`, `deploy/run.sh→npm run` (no Docker: single-language TS workspace, local tooling is enough for a one-person project).

## Start order of a batch
1. Integrator: `/next` on its `area-infra` story, merge; 2. `/integrate` what is In Review; 3. its report says which stories became Ready; 4. only then open the dev terminals. WIP: 2 devs + 1 in review (one person reviewing).

## Weekly (Edu, 15 min)
Read *Spec deviations* of closed stories → bump contracts if needed → move next stories to Ready → check `needs-human`.
